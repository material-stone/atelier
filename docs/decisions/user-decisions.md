# 사용자 판단 기록

사용자가 정한 방향과 요구사항, 그 이유입니다. Claude의 설계 판단은 [claude-decisions.md](claude-decisions.md)에 있습니다.

## 2026-11-10 · atelier 저장소를 material-stone 조직으로 이전

### GitHub 조직 이름은 material-stone, atelier를 그리로 옮긴다

- **결정:** 개인 소유 조직 `MaterialStone`의 이름을 `material-stone`으로 바꾸고(Claude 추천), 그 안의 `spell-agent`, `ark-zero`는 개인 계정 YouHyunwoo로 옮겼다. `material-stone-games`에서 Pages를 쓰는 저장소 넷 중 atelier만 먼저 `material-stone`으로 옮긴다.
- **이유:** 앞으로 쓸 조직으로 정리한다. 나머지(PokeDetective, 개인정보처리방침 페이지 둘)는 나중에 정한다.

## 2026-11-10 · CLI 줄바꿈 고정과 배포 설정 정리

### 배포에서 드러난 문제를 저장소에 반영한다

- **결정:** Claude가 제안한 후속 PR(CLI 줄바꿈을 LF로 고정, `SITE_URL` 예시 추가, npm 배포 절차 문서화)을 승인했다.
- **이유:** functions 배포와 npm 첫 게시에서 겪은 문제가 다음 배포 때 다시 생기지 않게 하기 위해.

## 2026-11-10 · atelier-cli 이름과 하위 명령, npm 배포

### 도구 이름을 atelier-cli로 바꾸고 하위 명령으로 구성한다

- **결정:** `atelier-upload`를 `atelier-cli`로 바꾸고, `atelier-cli login`, `atelier-cli upload`처럼 하위 명령으로 쓴다.
- **이유:** 업로드만 하는 도구가 아니라 로그인 등 여러 일을 하는 Atelier 명령줄 도구이므로 이름과 구성을 그에 맞춘다.

### 외부에서도 설치할 수 있게 npm에 등록한다

- **결정:** 저장소 체크아웃 없이 `npm install -g`로 설치할 수 있게 npm 패키지로 낸다. 실제 배포(`npm publish`)는 사용자의 npm 계정으로 한다.
- **이유:** 다른 PC나 다른 환경에서도 저장소를 받지 않고 바로 쓰고 싶다.

### npm 패키지 이름은 @material-stone/atelier-cli

- **결정:** Claude가 처음 정한 `@material-stone-games/atelier-cli` 대신 `@material-stone/atelier-cli`로 한다. Claude가 추천한 대로 GitHub 조직 이름도 나중에 소문자-하이픈 `material-stone`으로 맞출 계획이고, 저장소 이전은 나중에 따로 한다.
- **이유:** 앞으로 쓸 조직 이름 `material-stone`에 맞춘다. 아직 npm에 올리기 전이라 지금 바꾸면 비용이 없다.

## 2026-11-10 · 업로드 키 발급 서비스와 CLI 로그인

### Atelier에서 업로드 키를 발급한다

- **결정:** 키를 Secret Manager에 직접 넣는 대신 Atelier 사이트에서 발급한다.
- **이유:** 배포 전에 키를 준비해야 하는 순서 문제가 불편했다. 사이트에서 발급하면 그런 절차가 필요 없다.

### CLI 로그인까지 만든다 (Google 로그인)

- **결정:** Claude가 "기본형(설정 창 발급·폐기)을 먼저 만들고 CLI 로그인은 나중에"를 추천했지만, 사용자는 처음부터 CLI 로그인까지 만들기로 했다. 로그인은 사이트의 Google 로그인을 쓴다.
- **이유:** 키를 복사해서 붙여 넣는 과정 없이 바로 쓰고 싶다.

## 2026-11-10 · 업로드 API — 게임 정보 반영 시점, 전역 CLI·스킬

### 업데이트 때 바꾼 제목·설명은 업로드가 다 끝난 뒤에 반영한다

- **결정:** 게임 정보를 업데이트 요청 시점에 바로 바꾸지 않고, 새 빌드 업로드와 처리가 끝난 뒤에 바꾼다.
- **이유:** 업로드가 중간에 멈추거나 실패했는데 제목·설명만 먼저 바뀌는 것은 맞지 않다. Claude가 처음에 "남은 한계"로 두었던 동작을 사용자가 바로잡았다.

### CLI는 전역 명령으로, 사용법은 전역 스킬로 만든다

- **결정:** Claude가 제안한 "전역 CLI + 전역 스킬" 방식을 승인했다.
- **이유:** 다른 프로젝트에서도 같은 API 키로 편하게 올리고 싶다.

## 2026-11-10 · 업로드 API — 중단 처리

### 업로드가 중간에 멈췄을 때의 처리를 추가한다

- **이유:** 업로드가 끊기거나 중단되면 게임이 '처리 중' 상태로 남는 점을 확인했고, 자동화 도구라면 정리까지 되어야 한다.

### 다른 프로젝트에서도 같은 API 키를 쓴다

- **결정:** 프로젝트마다 키를 따로 발급하지 않고 하나의 키를 함께 쓴다. 그래서 키를 여러 개 등록하는 기능은 만들지 않는다.
- **이유:** 여러 프로젝트에서 같은 방식으로 간단하게 올리고 싶다.

## 2026-11-10 · 업로드 API

### 웹 업로드 룸은 그대로 두고, 웹페이지를 거치지 않는 업로드 API를 추가한다

- **이유:** 지금은 Claude가 브라우저를 조작해 업로드 룸에서 올리는데, 20MB가 넘는 파일은 Claude가 브라우저로 직접 올려 주지 않는다. 자동화 도구로 더 편하고 빠르게 올리고 싶다.
- **유지할 것:** 웹페이지 업로드 방식은 없애지 않는다.

### 앞으로 기능 추가·수정 때마다 결정 기록을 남긴다

- **결정:** 누가 어떤 판단을 했는지와 이유를 문서로 남기고, 사용자 판단과 Claude 판단을 나눠서 볼 수 있게 한다.
- **이유:** 나중에 왜 이렇게 만들었는지 되짚을 수 있게 하기 위해.
