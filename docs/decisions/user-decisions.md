# 사용자 판단 기록

사용자가 정한 방향과 요구사항, 그 이유입니다. Claude의 설계 판단은 [claude-decisions.md](claude-decisions.md)에 있습니다.

## 2026-11-10 · 업로드 API — 게임 정보 반영 시점, 전역 CLI·스킬

### 업데이트 때 바꾼 제목·설명은 업로드가 다 끝난 뒤에 반영한다

- **결정:** 게임 정보를 업데이트 요청 시점에 바로 바꾸지 않고, 새 빌드 업로드와 처리가 끝난 뒤에 바꾼다.
- **이유:** 업로드가 중간에 멈추거나 실패했는데 제목·설명만 먼저 바뀌는 것은 맞지 않다. Claude가 처음에 "남은 한계"로 두었던 동작을 사용자가 바로잡았다.

### CLI는 전역 명령으로, 사용법은 전역 스킬로 만든다

- **결정:** Claude가 제안한 "전역 CLI + 전역 스킬" 방식을 승인했다.
- **이유:** 다른 프로젝트에서도 같은 API 키로 편하게 올리고 싶다.

## 2026-11-10 · 업로드 API — 중단 처리

### 업로드가 중간에 멈췄을 때의 처리를 추가한다

- **이유:** 업로드가 끊기거나 중단되면 게임이 '처리 중' 상태로 남는 점을 확인했고, 자동화 도구라면 정리까지 되어야 한다.

### 다른 프로젝트에서도 같은 API 키를 쓴다

- **결정:** 프로젝트마다 키를 따로 발급하지 않고 하나의 키를 함께 쓴다. 그래서 키를 여러 개 등록하는 기능은 만들지 않는다.
- **이유:** 여러 프로젝트에서 같은 방식으로 간단하게 올리고 싶다.

## 2026-11-10 · 업로드 API

### 웹 업로드 룸은 그대로 두고, 웹페이지를 거치지 않는 업로드 API를 추가한다

- **이유:** 지금은 Claude가 브라우저를 조작해 업로드 룸에서 올리는데, 20MB가 넘는 파일은 Claude가 브라우저로 직접 올려 주지 않는다. 자동화 도구로 더 편하고 빠르게 올리고 싶다.
- **유지할 것:** 웹페이지 업로드 방식은 없애지 않는다.

### 앞으로 기능 추가·수정 때마다 결정 기록을 남긴다

- **결정:** 누가 어떤 판단을 했는지와 이유를 문서로 남기고, 사용자 판단과 Claude 판단을 나눠서 볼 수 있게 한다.
- **이유:** 나중에 왜 이렇게 만들었는지 되짚을 수 있게 하기 위해.
